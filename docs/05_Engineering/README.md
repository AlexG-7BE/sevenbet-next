# Engineering

## Purpose

Contains two distinct kinds of technical documentation:

1. Evidence-based documentation of the implementation as it exists today.
2. Approved engineering standards and shared delivery practices.

Target product architecture is documented separately in [`docs/02_Product_Architecture/`](../02_Product_Architecture/).

## What documents belong here

### Technical_Baseline/

A factual, evidence-based snapshot of the system as currently implemented. It records detected implementation evidence and is not a target architecture or an engineering standard.

### Engineering standards and practices

Normative rules for how the system should be developed, tested, secured, deployed, and operated, including:

- Engineering standards.
- Development workflows.
- Testing, security, and operational practices.
- Technical conventions that apply across the project.

Active Control Programme changes are additionally governed by:

- [`Programme-Architecture-Standards.md`](Programme-Architecture-Standards.md)
- [`Backend-Programme-Standards.md`](Backend-Programme-Standards.md)
- [`Programme-Definition-of-Done.md`](Programme-Definition-of-Done.md)

GB market and commercial authority are governed by:

- [`Great-Britain-Market-Authority.md`](Great-Britain-Market-Authority.md)
- [`GB-Commercial-Partner-Authority.md`](GB-Commercial-Partner-Authority.md)

Media ingestion and commercial creative handling are governed by:

- [`Commercial-Creative-Format-Contract.md`](Commercial-Creative-Format-Contract.md)
- [`Media-Ingestion-Contract.md`](Media-Ingestion-Contract.md)

## When this folder should be updated

Update `Technical_Baseline/` when documenting a newly observed implementation state. Update standards and practices when an approved engineering standard, delivery practice, or shared technical convention changes.
